# Language packs (schema 1)

LeanDuet separates mathematical proof structure from the language in which it is read or entered. Select a narrative language from the workbench toolbar, or import a UTF-8 JSON file (up to 256 KiB). Packs persist locally and never execute code. Built-in IDs en, zh, ja cannot be replaced. A community example is [French](../examples/language-fr.json); download its raw JSON and import it. It is a sample, not a comprehensive translation.

A pack has schema: 1, id (lowercase ASCII, 2–24 characters), label, words, grammar, rules and aliases. The words table has required keys assume, introduce, witness, let, apply, obtain, use, opaque, function, edit, hidden, limited. Use {name} for the identifier where appropriate. The rules table maps exact Lean declaration names to readable phrases. Missing rules use the generic application phrase. aliases maps declaration names to arrays of mathematical phrases. grammar has arrays prefix, using, join, establish, conclude, automatic; these are literal tokens, not executable regex. English / Chinese / Japanese built-ins and installed packs are accepted together by the controlled parser. Conflicting aliases are rejected instead of guessed. Rule availability is checked by Lean, not the pack. All rendering uses text nodes.

Interface language (English, Chinese, Japanese) is a separate preference from mathematical narrative language. Community packs extend mathematical narrative and controlled input, not interface chrome. Built-in exact-source examples have authored readings in all three languages. The Pages build also extracts their proof trees with the pinned Lean toolchain; those trees are read-only, shown only for byte-identical synchronized source, and do not constitute live verification. If the build-time data is absent, the static editor offers explicitly labelled authored readings instead. Keep grammar small; arbitrary prose, inflection and ambiguous notation need future grammar backends. See Ranta, Grammatical Framework (JFP 2004) for the separation of abstract and concrete syntax. Contribute JSON plus parser and rendering tests. Never include scripts, remote resources or executable templates.
