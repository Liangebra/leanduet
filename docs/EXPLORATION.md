# Mathematical exploration and formal commitment

Mathematics does not begin with a fully specified calculus. A mathematician may introduce a provisional notation, try an analogy, draw a conjecture, or change the question. LeanDuet should support this activity without forcing every sentence to become a formal command.

The Explore view stores arbitrary text independently of the controlled proof and Lean source. It has no grammar, no compulsory check, no AI requirement. It is exported verbatim as Markdown or included in a workspace export. Editing notes must not invalidate a Lean verification result for unchanged source.

A selected typed goal can be copied to exploration as a historical context snapshot. It is not a live assertion of correctness. The snapshot and subsequent ideas stay unverified. A selected delimited formula can be staged in goal search when a current proof goal is selected; only that selection is parsed. Parsing is not proof, and searching is not applying a proof. Neither action rewrites the surrounding notes or Lean source. Unsupported notation is kept verbatim in exploration.

The optional AI assistance is a separate, user-initiated operation. AI explanations append to notes with an unverified label rather than replacing the author's reasoning. A Lean proposal remains unverified until independently checked.

Our typed intermediate language describes the committed formal part of a document, not the limits of mathematical thought. Future work may include free-standing notebooks, multiple simultaneous conjectures, diagrams and local definitions, but none is implied by the current implementation.

## Working-object interface

The optional collection in the existing workspace format records stable local IDs, arbitrary labels, raw expressions, comments, informal references and author-assigned research statuses. Duplicate labels, empty expressions, cycles, dangling references, contradictory or unparseable statements are allowed. `discarded` retains the original attempt; `Try an alternative` creates a new object rather than overwriting it. These records are neither Lean declarations nor hypotheses. They have no inferred types and no automatic dependency resolution. The only mandatory validation is transport shape and storage limits (100 objects, bounded fields). Old workspaces without the optional collection restore to an empty collection. Markdown exports label every object unverified. A future semantic interface may attach a separately checked judgment to an object, without changing its raw expression.

A working object can be staged directly as a goal candidate. This is optional and uses only the selected expression, with the current typed goal as context; failed staging reports a diagnostic but leaves the original working object unchanged. Informal references are not interpreted as Lean assumptions. The local storage status is shown separately from mathematical status.

## Live interpretation and revision-aware reading

The typed goal's Explore interpretations panel accepts a bounded set of alternative lines. The deterministic planner recognizes a delimited formula, known rule/premise syntax, and ordered local applications. Only an enumerated set of discourse markers is separated; unknown modifiers and expressions remain unresolved rather than silently discarded. Distinct candidates are checked in one Lean invocation, with elaboration state restored between alternatives. The ordering prefers explicit, premise-directed interpretations over unconstrained formula search, then shorter printed terms. This is a heuristic, not a confidence estimate or an assurance that the mathematical intent is preserved. Each result is locally checked; full proof replacement still uses the independent patch verification. No AI provider is used by live interpretation. Optional debounced live typed reading refreshes the mathematical view after a synchronized Lean edit; revision checks reject stale results. Invalid or unsupported drafts are retained. Real-time here means debounced updates and bounded asynchronous local checks, not a measured latency guarantee. The current syntax remains limited; free text is not automatically translated in its entirety.

Author wording is recorded separately from formal reasoning and displayed in brackets. It survives a source revision only by an exact unique fingerprint of the occurrence's term, type, reference and visible scope; ambiguous or changed occurrences leave detached annotations available for copying into exploration. The algorithm is conservative, not a verified semantic alignment. Interpretation drafts can be explicitly saved to working objects.

For unrestricted wording, an optional explicitly authorized AI request can suggest several controlled interpretation lines. The raw text stays intact. The suggestions are displayed separately, can be edited, and are excluded from local checks until the author explicitly includes them. They pass through the same deterministic parser and bounded local verifier; a checked result establishes local type correctness, not a faithful translation of the original words. AI is not needed for the deterministic live loop, and no remote request happens automatically on keystrokes.

Browser regression coverage exercises a live source edit, a valid and an incompatible interpretation, retention of unsupported text, non-mutating candidate selection, and detaching author wording when the proof changes. This is a functional test, not a benchmark of interactive latency.

## Conversion performance boundaries

Live reading uses a reading-only extraction profile: it does not search local applications at every proof occurrence. The normal full extraction remains available. An exact-source single-entry browser cache avoids duplicate extraction within the same local session; it is a display cache, not a fresh verification result. Occurrence paths, annotation anchors and subtree sizes are indexed in one traversal. Unsynchronized edits retain a visibly stale, noninteractive previous reading instead of repeatedly deleting and rebuilding it; draft persistence is coalesced and flushed on page exit. The Lean process is still external and starts separately for each uncached inspection. No absolute latency claim is made.
